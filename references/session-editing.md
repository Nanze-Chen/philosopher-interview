# 会话记录、成稿与制作交接

## 角色与会话状态

默认用户是真实提问者，AI只扮演所选哲学家。主持人或编者用于框架说明、来源冲突和现代知识补充；不得自行假装用户已提出下一个问题。多位哲学家仅在用户指定的范围内切换，标明发言人，避免角色串线。

以下意图按语义识别，不要求用户背固定口令：

| 用户意图 | 动作 |
| --- | --- |
| 开始／继续访谈 | 读取人物档案和已发生的会话，接用户当前问题 |
| 跳出角色／先解释原文 | 暂停扮演，由编者回答；保留访谈状态 |
| 换人／进入圆桌 | 读取对应人物模型，明确新身份，保持同场上下文 |
| 先停一下 | 保存暂停状态；不自动宣告访谈结束 |
| 访谈结束／今天就聊到这里 | 自动整理本场可访问的完整记录，进入审稿 |
| 删除／保留／合并某轮 | 更新审阅稿和编辑映射，不默默重写其余部分 |
| 定稿／交给制作 | 输出制作稿和必要注释，列明实际交付状态 |

用户的叙述中引用“访谈结束”不等于发出结束指令；看实际意图。已经结束后又追问，可以续谈并更新稿件，不丢弃旧版本。

## 有记忆但不伪称全知

优先使用当前工作目录中既有会话约定。没有约定时，可在 `interviews/日期-主题/` 下保存 `dossier-人物.md`、`transcript-raw.md`、`session-state.md` 和 `manuscript-v1.md`；小场次可以合并档案与状态，避免空文件。不要把访谈生成记录写进技能安装目录。

当前聊天首次使用时，按SKILL.md简短介绍两种入口、直接提问、换人／跳出角色及结束成稿，并说明这是基于资料的模拟。已经介绍过就不重复；准备说明保持简短，重要分歧在涉及它的问答处说明。

每一轮完成后，在有文件能力和写入权限时追加原始记录并更新简短状态。使用不随编辑重排改变的ID，例如 T001。记录发言人、用户可见原文、人物回答、编者说明和来源／冲突／推演标记。时间戳只在实际可取得时记录，不倒造时间。现场语音仅有转写时说明“据可见转写记录”，不假称逐音核验。

状态保留：当前人物、直接对话／结合本书模式与解释框架、当前聊天是否已经给过使用说明（`usage_intro_shown`）、档案版本、最后轮次、已向听众介绍的概念／例子、仍有分歧的问题、用户删改决定。首次说明状态属于当前聊天，不因其他聊天中使用过技能就跳过，也不因同一聊天换人或开始新一场访谈而重置。多人课堂场景另区分已播、未播、跳过；只有实际已呈现的内容才能当作听众已知。

跨聊天恢复时只读取用户授权或当前任务相关、实际能访问的记录。工具只返回摘要就标为摘要，不补写缺失的逐字对白。内容过长时采用研究索引和会话摘要定位，再按需读取原轮；不要无声截断用户问题或把尚未讲过的资料写成共同记忆。

## 结束即自动生成审阅稿

先核对已记录的轮次、人物与缺口。完整取得就整理全场；发现缺失就标明缺失范围，先交付可恢复部分，必要时请求补充，不把不完整稿命名为完整实录。

输出适合阅读的访谈稿，并给一份简短编辑映射：

```markdown
标题；人物、模式与解释框架；书籍范围仅在结合本书时列出
说明：依据资料拟答；哪些段落是现代情境推演

## 正文
提问者：……
哲学家：……
编者说明：……（仅在必要处出现）

## 来源与解释注
按正文标记定位，不把拟写句子当引文。

## 审阅映射
| 稿件段落／题号 | 原始轮次ID | 保留、合并或删节情况 | 待决定事项 |
```

第一次自动整理默认保留实质内容，不替用户判断哪些观点“没用”。给出少量值得讨论的删并建议后，让用户决定；不要把整场编辑变成必须逐轮点批准的流程。

用户在结束访谈的同一条请求中已经明确删改时，核对全场后直接交付落实删改的审阅稿，不必先展示一份含已要求删除内容的稿件。

## 润色的边界

可以清理口头重复、明显转写错误、断裂语句和冗余称呼。必须保留问题如何发生：已经接受什么、为什么不信下一步、所用例子和替代解释。不要把一段有理由的质疑改成一句“这合理吗”。

人名和术语按上下文统一，例如数／树、逻各斯、赵林。涉及关键否定、数值或会改变论证的词时，语境不能唯一确定就保留待核，不猜。

用户说“删掉T004”通常是从稿件删除，原始记录保留并在映射注明。若用户明确要求原始记录也删除或隐去个人信息，按其要求处理相应可控记录；不能一边答应删除，一边把同样内容复制到附录。不要声称能够清除平台中不受本技能控制的聊天历史或备份。

删除上一答后，下一问可能失去指代对象。优先保留必要上下文、调整句子指代或补一小段明确标出的编辑衔接；不能为连贯编造用户说过的话、新史实或新的哲学论证。需要新增实质问答时作为候选插段交给用户，不混入实录。

合并几轮时仍能追溯原始ID；重排后检查概念是否先介绍后使用。重大解释冲突的两个答案和现代推演的身份不能因“口播更顺”而被删去。可以缩短说明，并把详细证据移到注中。

发现事实错误时先注明纠正及来源，再在新稿中修正，保留原始版本的编辑说明。用户已经认可的段落不因一次整体润色被任意重写。

用户要求“按批注修改”时，先读当前稿及其批注，按原句／段落ID定位；仅修改相关内容，记录已处理或待讨论的意见。不假定用户已经安装某个批注插件，或当前侧栏具备任意编辑功能。

## 制作交接

以用户确认的文字为准制作最终稿；审阅版不自动冒充已确认稿。交给用户指定制作方的材料包括：

- 干净的访谈正文，发言人清晰，可按完整语义拆段。
- 不朗读的来源、解释冲突和情境推演说明；在正文保留必要身份提示。
- 需要时提供角色表、术语读音待核项、适合动画展示的关键例子。时长只能估算，未录音不能报实际时长。

若后续流程需要结构化数据，沿用制作方现有格式，并保留原轮次／段落映射，不自行发明一套与现有站点不兼容的接口。动画和配音不能倒过来删掉问题的论证。

生成文件、发送文件、制作网页、发布网页是不同完成状态。按实际结果报告。只有任务明确要求实际发送且收件渠道已确定时才调用发送工具；若只知道姓名，先准备好文件，再解决渠道，不猜地址。
